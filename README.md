# 青禾校园点餐

校园多商家点餐小程序 + 若依总后台 + 若依商家工作台。已在本机连接 Docker MySQL、Redis 并验证核心业务流程。

商家后台采用**独立账号、独立菜单和后端数据隔离**，共享若依程序与数据库。每家商户只看自己的店铺、商品、订单和统计；总管理员管理所有商家。当前不是为每家店部署一套独立服务器。

## 位置与距离

首页点击“选择位置”进入定位页。H5 使用浏览器定位，小程序使用 `uni.getLocation`（WGS84）。只在用户点击定位按钮后请求权限；拒绝、超时或失败可手动选择商家区域。首页位置仅在本次应用会话内使用，返回页面时检查10分钟有效期。地址管理中的“收货点”单独定位并随地址保存到数据库，用于配送范围判断。

- 城市名称：后端支持百度地图逆地理编码。在根目录 `.env` 配置 `BAIDU_MAP_AK`（服务端 AK，开通逆地理编码并配置服务器 IP 白名单），重启后端生效。Key 不进入小程序。未配置或解析失败时显示“当前位置”，不显示固定城市。定位页说明坐标会用于地图查询；未配置 Key 时不调用第三方。
- 商家坐标：总后台或商家后台 → 店铺编辑 → GPS 纬度 / GPS 经度，两项一起填写或留空，统一 **WGS84**，不要直接混用高德/腾讯 GCJ02 或百度 BD09 坐标。CSV 模板含可选 `latitude`、`longitude`，兼容不含坐标的旧模板。
- 距离为直线估算，不是骑行路线；缺少店铺坐标显示“距离待完善”，未定位显示“定位后查看距离”。距离优先把未配置坐标的店铺放在最后。示例商家尚无真实坐标，未编造坐标。
- 浏览器定位需 localhost / HTTPS 与系统权限；微信产物已声明位置用途和 `requiredPrivateInfos`，上线前还需在微信公众平台完成对应接口权限与隐私保护指引配置。尚未在真机验证定位授权，也未用真实地图 Key 验证城市解析。
- 测试：`node scripts/test-location.mjs`、本地服务启动后 `node scripts/test-location-api.cjs`。覆盖距离算法、空值/0坐标、跨日期变更线、授权拒绝、超时、旧请求覆盖防护、后端校验、店铺隔离、缓存失效和导入回滚。

参考：[uni-app 定位接口](https://uniapp.dcloud.net.cn/api/location/location)、[百度地图逆地理编码](https://lbs.baidu.com/docs/webapi?title=reverse_geocoding%2Fguide%2Fwebservice-geocoding-abroad-base)。

## 本机启动

在项目根目录运行：

```powershell
npm start
```

脚本会启动独立的 `moxuany-mysql`、`moxuany-redis`，以及后台、小程序和 API。依赖缺失时自动安装。日志在 `.runtime/`；已有监听端口会被保留，若被别的程序占用请先处理端口冲突。

环境：Java 17+（本机21）、Maven、Node.js 20+、Docker。脚本优先使用 PATH，也兼容当前电脑 Maven 和 Docker 的实际路径。新环境需按安装位置调整脚本备用路径，或将软件加入 PATH。

```powershell
# 独立启动 / 构建
npm run dev:server
npm run dev:admin
npm run dev:miniapp
npm run build:admin
npm run build:h5
npm run build:miniapp
# Java 构建：先停止后端，Windows 下运行中的 JAR 会被锁定
mvn -f server/pom.xml clean package -DskipTests
```

`scripts/configure.cjs` 首次生成随机本地数据库密码、JWT 密钥，保存于忽略提交的 `.env`；不会覆盖已有配置。数据库首次初始化执行 `server/sql/` 和 `database/03-food.sql`。已有卷不会重复执行初始化脚本；`npm start` 会运行 `scripts/upgrade-local.cjs` 非破坏性补齐库存版本、商家/收货点坐标、营业时间、配送半径字段及分页/提醒索引。不要为了升级删除数据卷。

MySQL `127.0.0.1:13306`，数据库/用户名 `moxuany`，密码见 `.env`；Redis `127.0.0.1:16379`，业务使用 DB 1。容器只绑定本地回环地址，不会替换或清除其他容器数据。

## 商家入驻与操作

1. 总后台登录，进入“校园点餐 → 商家管理”，新增或导入商家。
2. 对该商家点击“开通账号”，设置商家登录名和初始密码。总后台可在若依用户管理中停用或重置账号。
3. 商家用自己的账号登录同一后台地址，只会获得“校园点餐”权限。
4. 在菜品管理中新增菜品或下载 CSV 模板批量导入；上传菜品图片，设置价格、库存、分类与上下架状态。
5. 小程序提交订单并模拟支付，商家订单工作台接单，依次更新制作/配送或待取餐/完成。

商品编辑带 `version` 乐观锁。若有人在编辑期间下单或其他人改过商品，会提示刷新后重新编辑，避免旧库存覆盖新扣减。现有订单保存菜品名称/价格/图片快照，不随菜单修改而变动。

## 并发与验证

- MySQL InnoDB 事务包住订单、明细、库存和优惠券。
- 商品按ID顺序加锁，条件更新 `stock >= quantity` 防超卖；取消与到期释放库存。
- `(member_id, request_key)` 唯一键实现幂等，校验请求摘要，防相同标识被用于不同订单。
- 状态流转锁定订单，防重复支付、重复取消、重复积分入账；15分钟超时，每30秒扫描一批100单。多实例重复扫描仍由行锁和状态校验保护。
- Redis 存储会话、Lua限流计数以及30–44秒的目录缓存。支付、库存和价格判断均以数据库为准。目录缓存不可用时回源；身份验证和限流依赖 Redis 可用性。
- 商家数据权限使用登录后的若依用户ID，列表、详情、修改、统计、批量导入均在服务端校验。

执行 `npm run test:integration`。**仅在本地演示环境运行**：会关闭本地若依验证码（保留账号密码验证）、新增测试用户/订单和一个测试菜品，测试结束下架该菜品，历史订单保留方便审查。不要指向生产库。

最近实测结果见 `docs/test-report.json`：100个并发请求抢9份库存，9单成功、库存不为负；16个重复请求仅1单；8个取消仅回补1次。50并发读取商家列表500次的吞吐和P95也记录在报告。**本机短时检查不是生产容量承诺**，上线容量取决于机器、数据量、热点商品比例、网络和实例数。

额外验证：`node scripts/test-csv.mjs`覆盖Excel UTF-8 BOM、逗号、引号、换行与非法CSV；`node scripts/test-upload.cjs`验证商家图片上传及三端静态图片访问；`node scripts/test-extended.cjs`验证实际超时任务、积分兑换并发和反馈回复。这些脚本仅供本地演示环境使用。
