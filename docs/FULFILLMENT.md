# 评价、预约限量、配送异常与取餐核销

## 入口与规则

### 评价闭环

- 顾客在已完成订单中评价。提交成功后展示原评分、原评价及商家回复，不再显示填写表单。
- 总后台或商家在「订单管理 → 顾客评价」分页查看并回复。每条评价允许一次公开回复，重复提交相同内容安全返回，不覆盖旧回复。
- 店铺评分按全部真实评价的算术平均值保留一位小数；没有评价显示“暂无评分”。既有演示评分在升级时重新计算，退款不删除历史评价。
- 同一订单只能有一条评价；顾客归属和商家数据范围均由后端校验。并发评价使用店铺行锁串行更新评分。

### 预约限量与按日库存

1. 「商家管理 → 编辑 → 开放预约」配置每半小时最多接单数，默认20单，范围1至10000。
2. 「商品管理 → 预约库存」选择北京时间日期，配置菜品及规格、加料的总配额。可提前配置今天起31天内的库存；用户可预约范围仍由店铺的1至7天设置决定。
3. 顾客在店铺先选用餐时间，再按对应日期库存点餐；结算页也可更改时间并重新核对购物车。

预约单使用用餐日期的独立库存，不扣即时库存。菜品、规格、加料必须分别有当日配额；未配置为0。总配额包含未支付预占、已支付及已售出数量，不能改到已占用数量以下；版本校验阻止旧页面覆盖新占用。

每个半小时时段按订单数限量，库存按份数限制。订单创建时同时占用名额与库存；未支付取消、到期取消、尚未制作的全额退款均只释放一次。已进入制作的退款不释放库存或时段名额。名额已满的时段从可选列表隐藏，结算中的旧选择会提示重新选择。降低限单数不取消已有订单，剩余名额不足时不接受新单。

升级前的预约订单仍退回原即时库存；升级时将仍有效的旧预约计入时段占用。日期库存不自动复制到未来日期，商家须明确配置。可运行 `node scripts/seed-operations-demo.cjs` 为“青禾体验厨房”补齐当前可预约日期的演示配额，脚本只创建缺失配额，不覆盖已配置数量。

### 配送异常

- 商家呼叫骑手后开始计时，超过10分钟无人接单时，后台顶部显示提醒，订单列表显示超时标记。后台每10秒检查提醒，每15秒刷新订单。
- 骑手在「配送工作台 → 我的配送」上报异常；上报后订单暂停确认送达，原骑手、顾客和后台都不能直接完成。
- 平台在订单详情中填写原因并派单/转派，或记录处理结果让原骑手继续配送。转派前需人工确认餐品交接安排。
- 「骑手管理 → 配送上限」设置每人同时配送的单数，默认5单，范围1至50，不能低于当前配送数。抢单与平台派单共用并发上限控制。
- 商家可以查看本店异常，只有总后台可转派或解除异常。停用、已满载骑手不可成为新受派人；旧页面的转派版本会被拒绝。转派后原骑手不能再完成该单。
- 接单、异常、处理、转派、骑手送达均在订单详情保留操作账号、时间和说明。提醒依赖打开的后台页面，未接入短信或微信订阅消息。

### 取餐核销

顾客自取单到「待取餐」状态后，向商家出示6位取餐码。商家在订单工作台点击「验码取餐」，输入正确代码后才完成订单。顾客自行完成和原状态修改接口都不能绕过核销。

错误码、未备好、退款处理中和非本店订单均拒绝核销。同一操作人对同一订单每分钟最多尝试10次。重复核销不会重复奖励积分或增加销量；订单保留核销人、时间及履约记录。本版使用手动输入取餐码，没有摄像头扫码流程。
