# 接单提醒、营业规则和分页搜索

## 使用方法

1. 进入总后台或商家后台（http://127.0.0.1:5174）。所有后台页面顶部都有接单提醒。总管理员看到所有店铺，商家账号仅看到绑定店铺。模拟支付后订单进入“待接单”，点击“去接单”进入对应筛选；接单后提示数量自动减少。
2. 点击“开启提示音”允许当前页面播放声音。新待接单订单提示一次；等候超过 5 分钟显示超时数量，并最多每分钟再响一次。默认关闭声音。退出账号或刷新页面后需重新开启。
3. 商家管理 → 编辑：填写 GPS 纬度/经度（WGS84）、开始营业、结束营业、配送半径。时段使用北京时间，每日一个连续时段；两项留空为全天，22:00–06:00 表示次日 06:00 结束。开始时刻包含，结束时刻不包含；手动休息优先。
4. 配送半径单位米，0 为不限范围，最大 50000 米。填写范围时必须同时填写店铺坐标。小程序地址编辑新增“在收货处定位”，请在实际收货地点点击；修改地址文字后需重新定位。坐标保存在该顾客的地址记录中，不会发送到地图服务商。
5. 顾客超出配送半径或未标记收货点时，结算会提示修改地址或选择自取；自取免距离校验，但仍须在营业时间内下单。半径是直线距离，未接入道路路线/行政区多边形。已创建且仍有效的未支付订单可在原 15 分钟期限内完成模拟支付。
6. 首页搜索商家或菜品，本店菜单搜索菜名/描述；总后台和商家后台的商家、菜品列表均服务端分页。默认每页 20 条，后台下方翻页，小程序加载更多。后台菜品商家选择框支持输入商家名称远程搜索。

CSV 商家模板新增可选列 `open_time`、`close_time`（HH:mm）、`delivery_radius`（整数米）。旧模板仍可导入，新店默认全天、不限范围。现有店铺保持原配置，不会编造实际坐标或营业时段。

## 实现与边界

- 接单提醒每次请求完成后等 10 秒刷新，连接失败在提示条显示并延长至 30 秒重试；不叠加请求，不因每次刷新重复弹同一新单。只查询 PENDING，未支付订单不催接单。返回总数、超过 5 分钟的数量及最近 50 个待接单编号。
- 提醒依赖后台页面打开和登录有效。关闭浏览器后不推送，后台标签页可能被浏览器降频；尚未接短信、微信订阅消息、打印机或系统通知。代码验证了音频开关和播放路径，设备扬声器实际效果仍取决于本机声音设置。
- 下单事务在扣库存前校验营业时间、收货地址归属和收货点距离；校验失败整体回滚。范围以收货地址坐标为准，不用顾客浏览首页时的位置代替。
- `/food/app/catalog/stores` 和 `/food/admin/catalog/stores` 返回 `{rows,total,page,pageSize}`；支持 `q/zone/category/lowFee/sort`，距离排序需 `latitude/longitude`。
- `/food/app/catalog/products` 和 `/food/admin/catalog/products` 支持 `storeId/q/category/page/pageSize`。公开接口必传店铺；后台根据登录身份限制店铺。结算用 `ids` 批量查询已选商品（最多 50 个），不拉取完整菜单。
- `/food/app/stores/{id}/info` 返回营业信息和分类；`/food/app/catalog/zones` 返回可选择区域。新接口实时读库，搜索后分页、全局排序、参数化 SQL，`%/_` 按字面搜索。页码 1–10000，每页 1–100。
- 旧目录数组接口为兼容保留，原本缓存目录的压力测试结果不能直接当作新分页接口的容量指标。当前包含搜索使用 LIKE/EXISTS，数据大幅增长时需要按真实流量进一步评估搜索索引和分页方案。
- 已有卷由 `scripts/upgrade-local.cjs` 补齐字段和索引，无须删除数据库卷。微信真机定位、真实地图 Key 与生产性能尚未实测；微信支付仍为模拟支付。

## 验证

```powershell
node scripts/test-paged-catalog.mjs
java -cp 'server/ruoyi-admin/target/classes;server/ruoyi-common/target/classes' scripts/BusinessRulesCheck.java
# 先 npm start；使用项目本地演示数据库和已存在的演示商家账号
node scripts/test-business-features.cjs
```

`business-features-test-report.json` 记录接口验证结果。独立创建 23 家商家、25 道菜和临时顾客，覆盖跨页结果、租户隔离、搜索转义、距离排序、营业时间、配送范围、模拟支付后的新单/超时提醒和接单移除；finally 清理本轮专属数据。原 13 项订单并发回归、定位回归、47 条订单分页回归、CSV 与前端竞态测试也已通过。

浏览器已验证首页按菜品搜店、店内搜索、后台商家搜索、新单通知/超时数、提示音开关及待接单跳转。`business-features-preview.png` 中的 1 单是临时页面测试数据，验收后已清理。
