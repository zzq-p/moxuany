## 退款与取消

未支付订单可直接取消；15分钟未支付自动取消。已支付订单在详情页填写退款原因，商家/总后台在“订单管理 → 售后申请”中同意或拒绝。审核期间暂停订单流转和骑手接单，顾客可查看完整申请历史及回复。

批准后全额模拟退款。尚未开始制作的订单释放菜品、规格、加料库存；已制作、待配送、配送中或已完成订单不回补餐品库存。优惠券解除占用，已过期的券仍不能使用。已完成退款会撤回原订单奖励积分与销量；如果积分已经花掉，余额可为负数，后续奖励抵扣欠额。

拒绝后可以继续履约，顾客可以重新申请。后台使用申请编号审核，旧页面不能误批新申请；重复提交同一审核结果不重复返库存或积分。已完成订单仅在完成后24小时内接受线上申请，超出窗口联系平台客服。

商家缺货无法接单时，在已支付、未制作订单详情点击“缺货退单并模拟退款”，填写原因即可。没有真实资金流转、部分退款、退餐物流或微信退款回调。

## 规格与加料

“商品管理 → 规格/加料”打开配置窗口。规格价格为整份菜品价格，加料金额在其上累加；后台按元输入，服务端按整数分存储。存在上架规格时必须选择一个规格，加料最多选10种。可把“大份·微辣”“小份·不辣”等组合建成独立规格，套餐配菜可建成加料；当前没有多组必选属性的组合生成器。

每个规格、加料独立价格、库存和上下架状态；同时受菜品总库存约束。每卖一份，扣菜品总库存和所有选中选项各一份。整单锁定商品后按固定顺序处理选项，条件更新防超卖，版本号防后台用旧库存覆盖最新库存。

同一菜品的不同配置可分行加入购物车。结算重新验证选项、价格和共享库存；订单保存当时名称和价格快照。每道菜最多保留30个选项，已有选项通过下架停用，避免历史退款找不到库存记录。规格配置暂在编辑窗口维护，菜品基础信息仍支持原CSV导入。

## 预约与分段营业

“商家管理 → 编辑”可设置最多4段每日营业时间，例如 `07:00-10:00,11:00-14:00,17:00-21:00`，支持跨午夜。填写后优先于原单时段设置；均为空则全天营业。使用北京时间，开店边界包含，关店边界不包含。

开启预约后设置可预约天数（1至7天，含今天）与提前备餐时间（15至240分钟）。顾客结算选择半小时间隔的可用时段，整个备餐区间都必须处于营业中。订单记录预约及开始备餐时间，到备餐时间后才进入商家接单提醒，提前接单会被服务端拒绝。

预约下单占用用餐日期的独立库存及半小时时段名额，仍需15分钟内模拟支付。菜品、规格和加料须配置当日配额；即时订单使用原库存。升级前订单保留原库存归属。配置变更只约束新下单，已建订单保留原时段快照。预约时刻表示期望用餐时间，不是骑手路线保证的精确送达时间。

## 配送工作台

外卖流程：待支付 → 待接单 → 制作中 → 商家“呼叫骑手” → 待骑手接单 → 骑手“接配送单” → 配送中 → 确认送达 → 已完成。自取为制作中 → 待取餐 → 商家输入6位取餐码核销 → 已完成。旧版商家手动配送接口保留兼容。

总后台在“骑手管理”创建、启停骑手账号。骑手登录后首页直接显示工作台，支持待接配送、我的配送、历史配送，每15秒刷新，每页20条。接单前只显示商家和订单基本信息，接单后显示收货信息；只可完成自己接的单。订单行锁确保同一笔配送单只有一名骑手接走。停用与接单使用同一骑手行锁，有配送中订单时不能停用。

本版提供人工抢单、平台派单/转派、异常处理与配送上限，不含自动派单、轨迹定位、导航、佣金结算或外部骑手平台接入。平台与商家继续在自己的订单工作台查看或处理订单。

## 地图选收货点

“我的 → 地址管理”先填写文字地址，再点击“地图选收货点”。H5 使用 Leaflet，可移动、缩放地图并点击宿舍等位置，无需人在收货处；也保留显式现场定位。确认点位后回填地址表单，保存地址才写入数据库。修改文字地址会清除坐标，需要重新确认对应点位。

微信端调用原生 `uni.chooseLocation`，将返回的GCJ02坐标近似转换为WGS84，与商家坐标、浏览器GPS和配送半径算法保持一致。manifest 已补充 `chooseLocation` 声明；微信公众平台的位置接口权限、隐私指引及真机运行仍需正式配置和验证。

H5默认使用 OpenStreetMap 公共瓦片，需要网络；未定位且无已有地址点时显示概览地图，不预设用户城市。可用 `miniapp/.env.local` 的 `VITE_MAP_TILE_URL` 替换为部署方允许的 **WGS84/Web Mercator XYZ** 地图服务，URL使用 `{z}/{x}/{y}`。不同服务的授权、署名及坐标系须匹配，不能直接换成GCJ02瓦片。公共瓦片不提供生产容量保证，地图加载失败会明确提示。地图选点不依赖百度逆地理编码Key，首页城市解析配置仍按README说明。

参考：[Leaflet](https://leafletjs.com/reference.html)、[OpenStreetMap 瓦片使用说明](https://operations.osmfoundation.org/policies/tiles/)、[uni-app 位置接口](https://uniapp.dcloud.net.cn/api/location/location)。

## 经营报表

“校园点餐 → 经营报表”，按北京时间下单日期查询，最多31天。总后台汇总所有商家，商家只看绑定店铺。统计支付金额、已批准退款、实收、订单数、取消率，以及每日汇总、前20名热销菜。

实收 = 已支付订单金额 − 已退款订单金额，包含履约中与申请退款尚未批准的订单。取消率 = 未支付取消数 ÷ 全部订单数；退款另计。热销份数和商品金额排除已退款订单，商品金额按订单商品快照计算，不分摊配送费与优惠。该报表按下单日期归集，历史退款会追溯影响原下单日，并非银行到账或退款发生日账单。

导出按钮按所选日期范围下载每日订单明细CSV（UTF-8 BOM），最多10000单，超限提示缩小范围；不导出顾客电话或地址。商家名称等文本做CSV转义与公式注入防护。

## 弱网恢复与超时清理

建单前先同步持久化当前账号、原请求体、幂等键及购物车摘要。断网或超时后首页、订单页和结算页显示待确认入口；先按原账号与幂等键查询，未查到可原样继续提交，同一请求不会另建订单。成功先保存订单编号，再清空仍匹配的购物车并跳转。明确回滚的业务拒绝才解除待确认；网络错误、限流和未知异常保留原请求。当前仅允许一笔待确认下单，切换账号不会替其他账号处理。

请保留原登录身份与设备存储。演示身份退出后无法找回，主动清除浏览器数据或卸载应用也会丢失本地恢复记录；数据库中的订单仍存在。未模拟浏览器物理断网，恢复逻辑通过持久化状态测试与服务端并发幂等/查询测试验证。

超时任务每秒运行，每轮最多500笔、约800毫秒工作预算；每笔独立事务，以 `FOR UPDATE SKIP LOCKED` 领取过期未支付单。库存与券释放和取消状态同事务提交；单笔失败回滚并延后60秒重试，避免堵住整个队列。进程重启后从数据库继续扫描，不依赖内存计时器；支持多个服务实例分担，但本轮只测试本机单实例。
