# 业务与权限设计

## 部署边界

一个 Spring Boot 应用承载若依和点餐业务；一个 Vue 3 管理端供总后台和商家使用；一个 uni-app 项目产出 H5/微信小程序。商家是逻辑租户，当前不单独分库或部署。

`food_store_user(user_id, store_id)` 绑定若依用户与店铺。用户ID唯一，一个商家账号只属于一个店铺，一个店铺可有多个员工账号。`FoodScope` 从 Spring Security 的登录用户读取身份，只有若依内置总管理员ID1拥有全平台数据权限。不能依靠改URL、传storeId或自己声明角色扩大权限。

商家角色100仅关联经营概览、店铺、商品、订单菜单；`food:manage` 控制业务接口入口，数据作用域再控制实际记录。用户与客服反馈为总后台专用。总管理员如给其他账号分配系统管理权限，应单独评估，不要把系统管理员角色分配给普通商家。

## 下单事务

1. 解析小程序 Redis 会话，按用户做30次/分钟下单限流。
2. 校验商品数量、类型和幂等键，按商品ID聚合并排序。
3. INSERT订单，利用用户+幂等键唯一索引阻塞并发重复请求，读取已提交结果前比较请求摘要。
4. 校验店铺手动营业状态和北京时间每日营业时段（支持跨午夜）、收货地址归属。设置配送半径的外卖店铺还校验已保存收货点与店铺 WGS84 直线距离；自取免距离校验。
5. 依次锁商品行并条件扣减库存，服务端计算整数分金额并保存商品快照。
6. 锁并校验当前用户优惠券、有效期和门槛，绑定订单。
7. 若客户端传入 expectedTotal，则比较顾客确认的金额与服务端计价；不一致时提示重新确认，整体回滚订单、库存、优惠券。该字段也参与幂等摘要；旧客户端未传时保留原协议。
8. 写最终金额并提交。任何一步失败整体回滚。

## 订单列表读取（2026-09-28 更新）

顾客订单接口在数据库中按当前用户、配送类型、状态过滤后分页，每页20条，按 created_at/id 降序稳定排序。类型、状态和页码经过白名单/范围校验。商品明细使用 IN 查询批量拉取，非空一页固定2次业务 SQL，避免原来的每单追加一次查询。增加 idx_order_member_filter(member_id,type,status,created_at,id)，已有卷通过 upgrade-local.cjs 补齐。

客户端切换筛选会重新请求第一页，并丢弃旧请求返回结果；加载更多期间禁止重复请求并按订单ID去重。详情页使用请求完成后再计时的轮询方式，已完成/已取消不再轮询，页面隐藏和销毁时取消计时与未完成请求的视图更新。

## 状态机

```text
UNPAID → PENDING → PREPARING → DELIVERING → COMPLETED  (外卖)
                           ↘ READY → COMPLETED       (自取)
UNPAID → CANCELLED (用户取消/商家取消/超时)
```

只有模拟支付接口可以使未付款变待接单；商家接口不能伪造付款。相同目标状态重试幂等，其他跳级更新拒绝。终态不允许重新支付或回退。已支付订单退款不在当前范围内。

取消和支付通过同一订单行锁串行化。取消后回补商品库存并释放优惠券。完成后累计用户积分和商品/店铺销量，重复完成不会重复奖励。超时任务使用到期状态复合索引，30秒扫描100单；大规模超时积压可增加批次、任务分片或引入消息队列。

## 高并发边界

共享 Redis 会话和限流使后端可横向扩容；MySQL 为交易真实来源。当前热点商品仍会串行竞争同一行，适合常规点餐场景，不宣称秒杀峰值容量。进一步扩展需要基于生产流量分析热点、分区订单表、搜索索引和读写副本，必要时用消息队列拆出通知等非核心操作。

新客户端使用 `/catalog/stores`、`/catalog/products` 的服务端分页搜索，实时查库并先过滤后分页；商家作用域由后端限制，默认20条，最大100条。结算按已选商品ID批量刷新库存和价格，不拉取全菜单。旧兼容目录接口仍为有界陈旧缓存，库存展示可能落后30–44秒；提交订单始终重新查数据库。后台变更主动删除旧目录缓存，批量导入的并发读可能在提交前重新填充旧缓存，最长TTL后恢复。旧缓存接口的压力测试结果不代表新分页接口容量。

后台全局接单提醒通过 `/food/admin/order-alerts` 每10秒读取权限范围内 PENDING 汇总与最近50个编号，5分钟以上标为超时。只读查询有状态/支付时间索引；客户端去重新单提醒、音频显式开启、失败延长重试，不依赖数据库写通知状态。关闭页面后无推送。具体操作和限制见 BUSINESS-FEATURES.md。

后台库存修改必须携带当前version，库存预占/释放也增加version；旧表单被拒绝。不能用Redis缓存价格或客户端总价作为收款依据。

## 身份与模拟支付

演示开关只通过服务端环境变量设置，默认关闭，开发启动脚本显式开启。演示登录为每个新会话生成随机身份，并赠送一次新客券；没有生产防薅新客券机制。演示开关开启的服务应仅用于演示。

微信真实登录路径接收 code，服务端调用微信换取openid，不把AppSecret返回前端。当前未提供微信支付下单/验签回调/退款，不可对真实支付使用当前模拟端点。
